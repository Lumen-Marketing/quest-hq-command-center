🛡️ Abe’s nightmare — solved

File-upload security hardening

“What if someone uploads a malicious file?” — every upload path in the app now answers that, in three layers.

Layer 1 · Frontend

The accept filter

The picker only offers allowed types. A nicety — easily bypassed with DevTools, so never trusted alone.

Layer 2 · Surface check

Extension + MIME

Extension and MIME must agree. Dangerous and double extensions (invoice.pdf.exe) are dropped instantly.

Layer 3 · The truth

Magic bytes

Read the real bytes and confirm the signature. The binary never lies — a renamed file is caught here.

malware.zip → photo.jpg → ⛔ blocked by the magic-byte check

One shared policy

A single upload-policy.js module — per-context allowlists, size caps, filename sanitization — wired into all 11 upload entry points.

Server backstop

The API endpoint validates extension + MIME + size; uploads declare a canonical Content-Type so bucket rules actually bite.

Bucket lock-down

A migration sets allowed_mime_types + file_size_limit per bucket, makes doc buckets private, with folder-scoped RLS ready to enable.

Proven by tests

Seven new regression tests, including the exact renamed-malware case, lock the behavior in.
