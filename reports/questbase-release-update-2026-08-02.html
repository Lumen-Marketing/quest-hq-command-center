What's new

Pipeline stages & board view Ready

Records can now be worked as a pipeline. A new Board view sits beside Table and Cards, with one column per stage, drag-and-drop between them, and a per-column record count and money total.

  • Manage stages — rename, recolour, reorder and delete. Each stage shows how many records sit on it before you delete it, and deleting asks where those records should go.
  • Stages are an existing Status field read as a sequence, not a new concept. Any app that already had one is already a pipeline, with nothing to migrate.
  • Records whose stage was deleted collect in a leading "No stage" column instead of disappearing — a board that silently drops records is worse than an untidy first column.
  • Dragging a card is treated as an ordinary edit, so automations, timestamps and saving behave exactly as they do on the record form.

Stage automations Ready

New trigger: a record moves between pipeline stages, expressed as from → to with either side left as "any stage". The existing trigger could already say "changes to Won"; this adds "leaves Quoted" and "moves at all".

It fires only when the stage genuinely changed — otherwise every save on a record would trip every pipeline rule attached to it.

Cross-company app install Ready

An app can now be installed into a workspace in another company you own: pick the company, then the workspace. Records and fields stay shared, and the picker states plainly that deleting a record from either side deletes it for both.

Saving writes both companies' documents, because a linked app's data lives with the company that owns it. Saving only one would have shown the edit on screen until the next reload discarded it — silently.

Floating message dock Ready

A circular button in the bottom-right corner, with an unread badge, opening three tabs:

  • Recent — conversations with previews and unread counts.
  • People — searchable member list showing who is online; click to message.
  • Guide — ask a question about Questbase.

Conversations open as a floating window over the page you are on, so you never lose your place. It reuses the existing messaging code for starting and sending, so permissions and attachment rules are unchanged.

The Guide is not an AI chatbot. It searches Questbase's curated in-product help — the same index behind the command palette. That means it cannot invent a feature that does not exist, it works offline, costs nothing per question, and no user text leaves the app. The trade-off: it only knows what is written in that help index, so a new capability needs a help topic added. The panel says this outright, so an unanswered question reads as "not covered" rather than a broken assistant. Wiring in a real language model is a separate decision — it brings API keys, per-question cost and data-handling questions with it.

Appearance: side menu themes Ready

Seven presets — Default, Midnight, Dark, Coffee, Hot, Forest, Light — plus Custom with your own menu and highlight colours, and an optional text colour that defaults to automatic.

  • Settings are per person. Changing your own look never affects your team. "Set as company default" remains a separate, permission-gated action that only reaches members who have not chosen for themselves.
  • "Default" applies no overrides at all, so the shipped look cannot drift as presets are edited.
  • Custom colours pick light or dark text from the background's actual brightness, so a chosen colour cannot end up unreadable.

Company & workspace icons Ready

  • A chosen icon now renders as a plain glyph — no tile, no border. Uploaded images keep their container, since an image has its own edges and crop.
  • Icon colour picker: nine presets plus any custom colour, defaulting to Quest orange.
  • The library grew from 47 to 124 icons in 10 groups, with Solid and Line styles.
  • Two brand marks — dark ink for light sidebars, light ink for dark ones — both generated from the single piece of brand artwork.

Everything ships inside the product. No icons are fetched from Google or any other third party, so the app keeps working offline and nothing about who uses it is sent anywhere.

Smaller improvements Ready

  • Phone numbers on workspace apps are now dialable.
  • The workspaces rail is collapsible; "+" adds a workspace and a per-row icon edits one.
  • Sidebar collapse uses a single rotating chevron with a smooth transition.
  • A proper loading animation replaces the plain "loading" text.
  • Online/offline rings on chat avatars.
  • Contact labels are stored as durable rows rather than written into the notes field.
  • No more jumping to the top of the page when ticking a task, hiding a field, choosing an install company, or moving a card on the board.

Bugs found and fixed

IssueCause and resolution
Blank page on load Twice. First, a function moved into a deferred module was still called while drawing the first screen. Second, two lookup tables were declared below the code that reads them during start-up. Both fixed; automated checks now catch each class of error.
Build reported success while shipping a blank page The safety check that exists for exactly this problem detected it, printed a warning, and then reported success anyway. It now fails the build. This is the most significant fix in this batch — a check that detects a fault and passes is worse than no check, because it is trusted.
Unreadable sidebar text On dark themes, the product and company names stayed near-black on navy: those elements carry their own colours and were not covered by the theme. Fixed, with a test asserting every colour in that section is theme-driven rather than fixed.
Board jumped to the top on every change The scroll-preservation logic refuses to act when it cannot uniquely identify the scrolling area — and a board has one scrolling list per column, all alike. It now identifies each column individually.
Empty chart claimed a total of 1 A single value served as both the divide-by-zero guard and the printed figure. Found only because the chart code was moved somewhere it could be tested directly.
